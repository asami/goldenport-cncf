## Per-instance composition and activation

Each Subsystem retains immutable admitted provider/period/candidate values, an exact
ID-to-provider table and one local owner. Registration is possible only before final
initialization. There is no global provider registry, class loading/reflection,
discovery or fallback. The fixed provider start first enters the original fresh-engine
barrier, then builds all explicit native inputs under the existing managed binding
lease. One leased EntityStore and BlobStore delegate each native overload exactly
once, retain exact Failure/throw semantics, and merely mark sticky degradation.

The owner constructs the existing Store, keyed bridge, owned payload quota, lifetime
quota, retention, cleanup and maintenance. Native provider capability, policy equality
and persistent Blob readiness must pass before discovery. Discovery is fetched once. Default and explicit-false
`migrateV1OnStartup` retain the original source fetch -> bridge bind -> recovery
effect order. Trusted registered composition may explicitly enable the private
Boolean only with an internal `job_admin` or `content_admin` Operator context.
After original native capability probes and that one discovery fetch, D2 runs
[explicit migration preparation](durable-job-migration-checkpoint.md) on the same
immutable cached vector before bridge binding or any original recovery. It uses
the owner's original Store, payloads and lifetime policy plus the actual engine
resource policy; the original provider-start SystemNode lease and begin barrier
cover complete native/paid/physical preflight, stream finally-close, sequential
original OCC checkpoints and exact acknowledged paid post-proof. No new monitor
encloses those operations. A refused or ambiguous suffix retains genuine native
prefix/current commits and conservative storage reservations without rollback,
refund or retry. The same entire cached candidates then enter the original
terminal and runtime coordinators; both original recovery passes remain required.
Each original identity/ordinal must report exactly one Registered terminal or runtime
result. A failed suffix retains any genuine paid prefix authority while the startup
barrier prevents execution, refund, rollback or fallback.

## State and synchronization

Begin rejects any original workers, bridge, native/runtime/terminal bindings, retained,
pending or executing resources, queued/bootstrap work or closed original admission.
During initialization submit/reserve refuses before IDs and native effects; manual
claim returns no work and original worker startup CAS stays guarded. Recovery uses
its original inner authentication/registration monitors. No new outer monitor encloses
those calls. After complete recovery, the final engine monitor checks closure, registers
one non-early fixed-delay maintenance callback, briefly acquires Subsystem to reject
its actual shutdown flags and publish the owner, attaches it, clears initialization and
releases original workers once. Engine-to-Subsystem is the commit lock order.
Shutdown releases Subsystem's monitor before original quiesce and owner stop/drain.

## Real lease, execution and maintenance

The outer gate routes generic effects through the actual Subsystem/SystemNode binding
lease. ThreadLocal nesting inherits an already admitted lease and is removed in finally.
Close denies new entries; admitted nested work continues while original binding drain
waits. There is no fake lease counter, alternate pool, physical-close adapter or join
inside maintenance close. The complete original sync/async/manual execution body,
including existing execution scheduling work, remains inside this lease. A body that
never enters releases its original resource reservation exactly once; after entry the
original native execution and settlement remain owners.

The scheduler's optional lease defaults to None for existing callers. A configured
callback checks Ready briefly, then holds the real lease around time/source/full sweep.
Its own monitor only protects generation, one registration and no overlap; it is never
held across a sweep. Close cancels future registration and closes the outer gate
before binding drain, retaining admitted callbacks without rearm or shared timer close.

## Closed operational data and cleanup

The public states are Unconfigured, Starting, Ready, Degraded, Closing and Closed.
Readiness requires actual native probes, full recovery and timer registration. Any
native delegated fault or adverse original maintenance facet degrades permanently;
ordinary kept/not-due/held/shared acknowledgement is healthy. The R15 same-canonical owned/shared ownership refusal remains adverse and protects bytes and charges. Getters only read owned
state and scheduler status, without I/O, source discovery, clock or ID calls.

Operator authorization precedes the engine health getter. The additive durable-health
record and durable-health/durable-maintenance categories contain fixed enum/Boolean
facets and actual availability. Original runtime-only counts and unavailable Phase
69.7 retention category remain unchanged. Startup failure is fixed and redacted,
marks admission failed, closes owner registration/gate, and uses original CLI cleanup.
Logical shutdown aggregates native quiesce/owner stop with service/resource/drain/
release/classloader cleanup, preserving cached repeat results and physical ownership.
