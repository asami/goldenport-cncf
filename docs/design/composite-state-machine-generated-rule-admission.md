# SWF-03: Producer-Generated Rule Admission Contract

## Purpose and boundary

SWF-03 admits a closed, typed set of rules generated by the producer for one
`CompositeStateMachineDefinitionIdentity` and version. Its sole input is that
producer-generated typed output, including the producer's source, model, and
source-location provenance. CNCF does not reparse Cozy or CML, infer semantics
from names, status, or raw source, or supplement the submitted rule set.

The admitted contract is definition- and version-bound. A rule set generated
for a different definition identity or version is not admissible for the
target definition.

## Closed typed generated input

The producer-generated input is a closed typed contract containing:

- the bound `CompositeStateMachineDefinitionIdentity` and version;
- source, model, and source-location provenance supplied by the producer; and
- a complete finite set of generated rules, each with a stable generated rule
  identity, exact role reference, exact state reference, a
  `CompositeStateIdentity` output, and its own deterministic source, model, and
  source-location provenance. Rule provenance is retained on every generated
  rule; it is not supplied only by the enclosing contract provenance.

Rule identity is stable within the definition identity and version to which it
is bound. Role and state references are exact contract references, not names
to be interpreted or matched heuristically. The output is the explicit
`CompositeStateIdentity` generated for that rule.

The producer is responsible for static analysis of its model and source before
submitting this typed contract. That analysis explicitly diagnoses generated
rule reachability, model coverage, and rule overlap. SWF-03 admits or rejects
the submitted contract from those producer-supplied diagnoses; it neither
reconstructs producer analysis nor repairs its result.

## Fail-closed admission

Admission fails closed when any required contract property is absent,
inconsistent, invalid, or cannot be established from the typed producer
output. Rejection categories include:

- missing, invalid, or target-mismatched definition identity or version;
- missing required producer provenance, or provenance that does not identify
  the supplied source, model, and source location;
- an absent, partial, non-finite, or otherwise non-closed generated rule set;
- missing, unstable, or duplicate generated rule identities;
- a rule with a missing, invalid, or non-exact role reference, state reference,
  or `CompositeStateIdentity` output;
- a generated rule with missing or nondeterministic source, model, or
  source-location provenance;
- missing or incomplete producer diagnoses for reachability, coverage, or
  overlap, or static-analysis findings that make the generated contract
  inadmissible; and
- any opaque extension, untyped content, or condition that requires CNCF to
  derive semantics from CML, names, status, raw source, or a fallback.

There is no priority rule, default rule, partial admission, extension point,
or runtime repair path. A rejected producer contract is not transformed into
an admitted one by SWF-03.

Every incompatible or unadmitted contract/configuration produces the
structured `RejectedAdmissionConfiguration` outcome. It records the rejection
kind, stable reason, target definition identity and version, submitted
identity and version when present, and the affected rule identities with their
source/model/source-location provenance when available. This outcome is
terminal for that admission or evaluation attempt and selects no composite
state; it is distinct from `UnmappedConfiguration` and
`AmbiguousConfiguration`, which are reserved for runtime evaluation after a
contract has already been admitted.

## Evaluation boundary

Producer static analysis determines whether its generated rule contract is
admissible. After admission, SWF-02 performs runtime evaluation against the
already admitted typed rules and requires exactly one matching rule for the
runtime inputs under that contract.

An evaluation that matches no admitted rule yields
`UnmappedConfiguration`. An evaluation that matches more than one admitted
rule yields `AmbiguousConfiguration`. Neither outcome is resolved by priority,
defaults, inferred intent, partial rule use, or runtime repair. These are
runtime evaluation outcomes, distinct from SWF-03 admission rejection of the
producer-generated contract itself.

## Examples

### Accepted contract

A producer supplies a typed, closed rule set bound to definition identity
`OrderComposite` at version `3`, with source, model, and source-location
provenance. One generated rule has stable identity `order-v3-r17`, exact role
reference `Approver`, exact state reference `Approved`, and output
`CompositeStateIdentity` `AwaitingFulfillment`, retaining its own deterministic
source, model, and source-location provenance. The complete submitted set has
the required typed fields and passes producer static analysis for reachability,
coverage, and overlap. SWF-03 admits that set; it does not inspect the
underlying CML or derive further rules.

### Rejected admission

A producer supplies a rule set bound to `OrderComposite` version `2` for a
target at version `3`. Even if individual rules appear usable, the definition
version is target-mismatched. SWF-03 rejects the entire submitted contract;
it does not admit a subset, reinterpret the version, or request a runtime
fallback.

### Unmapped evaluation

An admitted rule set contains rules for the exact combinations represented by
its producer-generated typed contract. At SWF-02 runtime, the current exact
role/state configuration matches none of those rules. The result is
`UnmappedConfiguration`; no default composite state is selected.

### Ambiguous evaluation

At SWF-02 runtime, the current exact role/state configuration matches two
admitted generated rules. The result is `AmbiguousConfiguration`; neither rule
is preferred and no composite state is selected.

## Adjacent responsibilities

Cozy and CML remain producer-side concerns. SWF-03 receives their result only
as the closed typed producer-generated contract and has no CML parsing or
semantic reconstruction responsibility.

`CommittedTransition` is not an SWF-03 admission input. Phase 63.2 supplies it
only after commit to SWF-02's later runtime derivation boundary. SWF-03
neither observes raw events nor triggers before commit.

SWF-04 through SWF-07 are outside this contract. Their responsibilities do
not expand SWF-03 admission, evaluation, error handling, or recovery.

Phase 77 and `ComponentFactory` are outside the admission boundary; SWF-03
does not define construction, factory, or component lifecycle behavior.

Phase 85 is also outside this boundary. SWF-03 does not define durable
behavior, persistence, callbacks, action behavior, wire encoding, or other
runtime integration behavior.
