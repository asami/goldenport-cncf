# OLAP／BI・業務帳票・印刷の接続基盤 開発候補計画

Date: 2026-11-02
Status: Promoted to Phase 119 / 計画経緯・未着手
Owner: CNCF
Phase: [119](../phase/phase-119.md)

## 目的と範囲

専門家が構築するOLAP／BI、帳票生成、印刷システムをTextus／CNCFへ接続するため、次の3契約を整備する。

1. データ供給契約
2. 帳票生成の接続契約
3. 印刷依頼・結果の契約

分析指標・分析モデル・ダッシュボード、個別帳票の様式・レイアウト、プリンタードライバー等は専門家・外部システムの担当とする。CNCFは公開契約、実行コンテキスト、権限、共通の実行・記録への接続を担う方向で検討する。各機能の実装先は既存コンポーネントとプロバイダーの責務を調査して決める。

本計画はPhase 119へ昇格した。現在の計画と進捗は[Phase本文](../phase/phase-119.md)と[checklist](../phase/phase-119-checklist.md)を正本とし、本notesは計画経緯として保持する。既存開発の優先順位は変更しない。仮仕様は[検討journal](../journal/2026/11/2026-11-02-data-report-print-provisional-contracts.md)を参照する。

## 開発項目

| ID | 項目 | 作業 | 成果物・受入れの目安 |
| --- | --- | --- | --- |
| DVL-DATA-REPORT-PRINT-01 | データ供給契約 | 既存Query/View/Record Exportを調査し、型・意味・取得条件・時点・権限・大量取得の契約を定義する | 契約仕様、最小接続例。権限外データが出ず、複数ページを取得しても指定の整合条件を保持する |
| DVL-DATA-REPORT-PRINT-02 | 帳票生成接続 | 専門帳票エンジンへの入力・テンプレート版・ロケール・生成物・失敗の契約を定義する | 契約仕様、プロバイダー接続例。データ時点とテンプレート版を追跡でき、閲覧と再出力を権限制御できる |
| DVL-DATA-REPORT-PRINT-03 | 印刷依頼・結果 | 印刷サービスの受理、処理状況、確認可能な完了、取消し、結果不明、再印刷を定義する | 契約仕様、接続例。受付を物理完了と誤認せず、応答断から無条件再送しない |

## 当初の実施順序（履歴。進捗はPhase 119 checklistを参照）

- 既存仕様・実装・進行中Phaseを調査し、重複と責任分界を確認する。
- DVL-DATA-REPORT-PRINT-01の最小契約を仕様化する。履歴保存やCDCの追加は必要性と既存機構を確認して別途決める。
- 権限付きデータ取得から外部への受渡しまでの最小接続例を検証する。
- DVL-DATA-REPORT-PRINT-02の契約と最小帳票エンジン接続を整備する。
- DVL-DATA-REPORT-PRINT-03の契約と最小印刷サービス接続を整備する。
- データ供給→生成→保存→印刷→結果照会→明示的な再印刷の受入れ例を通す。
- 専門家向けtechnical guideと接続サンプルを整備する。

帳票生成はデータ供給契約に依存する。印刷契約は生成済み文書も入力にできるようにし、特定の帳票エンジンへの依存を避ける。既存Job、Workflow、Provider、Blob、監査の契約を再利用し、同じ責務の独立した実行基盤を増設しない。

## 着手時に決めること

- 契約と実装の所有先、具体的なプロバイダーと対応範囲
- 全件取得、差分取得、時点指定の初期対応範囲
- データ取得・生成物保存・外部転送・印刷それぞれの権限
- 保存期間、削除、監査情報の範囲
- バックグラウンド処理時の主体・ロケール・権限再確認
- 運用上の上限、結果不明時の復旧手順、実機による印刷完了確認の可否
