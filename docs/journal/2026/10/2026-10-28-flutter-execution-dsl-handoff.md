# Flutter実行DSLの追加とsm-workflowへの受渡し

Date: 2026-10-28 (Asia/Tokyo)
Status: 設計方針合意・実装計画。実装、検証、配備は未実施。
Audience: CNCF開発、sm-workflow開発。

## 合意した責務境界

CNCFには `flutter_build`、`flutter_test`、`flutter_analyze` の型付きDSLを追加する。
既存の `sbt_compile`、`sbt_test` などはSBT固有の操作として維持する。
`sbt_xxx` の内部をツール非依存にしたり、Flutterを実行する経路へ転用したりしない。

| 所有者 | 責務 |
| --- | --- |
| CNCF | Flutter固有の要求・結果型、3つのDSL、UoW接続、実行、出力解釈 |
| CNCFの既存基盤 | プロセス起動、待機、期限、キャンセル、終了確認、ログ・成果物収集 |
| sm-workflow | SBT／Flutter結果の共通化、検証計画、修正・レビューへの進行、正式受入れ |

共通のWorkflow検証モデルはsm-workflowが所有する。CNCFはFlutterの実行事実を返し、
親Phaseの合否や継続方針を決めない。CNCFの検証完了もsm-workflowの統合合格を意味しない。

関連する受信側journal: sm-workflowリポジトリの
`docs/journal/2026/10/2026-10-28-tool-neutral-validation-handoff.md`。
クロスリポジトリ参照はリポジトリ名と相対パスで示し、特定端末の配置を前提にしない。

## DSLと結果の設計

- `flutter_build`: 対象Workspace、ビルドターゲット、モードなどの型付き条件を受け取り、
  実行結果と実際に生成された成果物への参照を返す。
- `flutter_test`: 全体または明示的に選択したテストを実行し、選択対象、実行確認、
  成功・失敗・スキップ等の集計と診断を返す。
- `flutter_analyze`: 静的解析を実行し、診断と実際の解析結果を返す。

`FlutterExecutionResult` 等の具体的な型名・シグネチャは実装時に仕様として確定する。
操作、対象、実行終了状態、Flutter固有の結果、診断、ログ・成果物参照を表現し、
起動前拒否と実行状況不明も区別する。終了コード0だけからテスト実行や成果物生成を捏造しない。
テスト0件、全件スキップ、選択対象未確認、不完全な出力は観測どおりに返し、
それを許容する受入れ条件はsm-workflow側に残す。

DSLの構築を実行と同一視せず、既存のUoWとプロセス管理に接続する。
実行環境側がFlutter SDK、作業ディレクトリ、実行条件を解決する。
AIが渡す任意シェル文字列を新しいDSLの入力にはしない。
ログの解析・集計はプログラムで行い、AI向けには要約と必要な詳細参照を提供できる結果にする。

初期範囲は静的解析、通常テスト、明示したターゲットのビルド。
実機・エミュレータのライフサイクルを伴う統合テスト、配布・署名・公開の自動化、
汎用的なプラグイン基盤やネストWorkflow管理はこの初期範囲に含めない。

## 実装計画

1. **C1 — 型と実行契約**
   既存のSBT DSL、UoW、プロセス管理との接点を確認し、Flutter要求・結果・診断を仕様化する。
   対象SDK、ビルドターゲット、モード、選択テストの表現と出力形式を確定する。
2. **C2 — DSLと実行接続**
   3つのDSLと対応する型付き実行経路を実装する。既存基盤の期限・終了・収集を再利用する。
   SBT操作の意味・結果を変えず、未対応条件は具体的な理由を返す。
3. **C3 — 出力解釈と実行仕様**
   対象SDKの機械可読テスト出力を確認し、最終結果まで集計する。
   成功、失敗、0件、スキップ、選択対象未確認、出力欠落、起動失敗、中断・終了未確認を扱う。
   診断・成果物と要求対象の対応を検証する。
4. **C4 — CNCF側検証と成果返却**
   コンパイル、関係するExecutable Specifications、既存SBT経路の回帰確認、
   実際のFlutterプロジェクトでの3操作と必要な独立レビューを完了する。
   実環境未確認の操作やターゲットは、fixture成功から実証済みとは扱わない。

## sm-workflowへの引継ぎ条件

CNCF側は自リポジトリの通常開発として実装・検証・必要なレビューまで担当する。
親sm-workflow Sessionの子Workflowにせず、ネスト管理の実装を先行条件にしない。
返却内容は以下とする。

- 変更したGit revisionと利用する成果物の版・場所。未コミット部分があれば明示する。
- 確定したDSL／型の仕様、利用例、必要なSDK・実行環境・対応ターゲット。
- 実行した検証、実際の結果と根拠、レビュー結果、残件・未確認条件。
- sm-workflow側が依存成果物を利用する方法。公開・配備は別の既存権限に従う。

「ソースを追加した」だけでは返却完了としない。sm-workflow側は返却成果を受け取り、
独自の結果変換・進行・再開・正式受入れを統合検証する。
このjournalは実装成功や配備済みの証拠ではなく、既存Phaseの完了状態も変更しない。
