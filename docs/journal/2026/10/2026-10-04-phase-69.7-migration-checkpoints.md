## Native codec and checkpoint gap

Original `DurableJobRecord.migrateV1ToV2` is a value conversion that preserves the
complete body and semantic revision. A durable native `Store.checkpoint` requires
contiguous semantic revision, exact observed provider revision and original
optimistic storage-accounting authority. D2 first uses that original conversion,
then signs V2 with only identity.revision advanced by one; it does not change any
other identity/timestamp/authorization/definition/input/result/external/CallTree/
task/schedule/retry/retention/timeline/diagnostic fact. LegalHold uses its original
`retainUntil=Some(Instant.MAX)` fact. Only Active terminal V1 with matching original
result/status and representable terminal descriptors is eligible; Long.MaxValue,
inactive/unknown/corrupt/raw V0 storage and incompatible contexts refuse.

Native canonical V0 ingestion remains unsupported. A signed V1 without genuine
Published lifetime authority also remains refused. Neither the value codec nor
Operator capability is evidence of payment. No synthetic Seed/Binding, guessed ID,
paid root, protected replay, resubmission or automatic migration is introduced.

## Sequential checkpoint and refusal semantics

Preparation freezes all source snapshots, destinations and footprints in original
candidate order. Each V1 source is reread exactly immediately before its one
original native checkpoint. Returned destination, actual post-checkpoint footprint,
existing prepare on that actual V2 acknowledgement and final exact provider
snapshot all remain necessary. Job writes retain original bounded storage reserve/
confirm behavior; one Job checkpoint does not mean only one native accounting CAS.

A race before application refuses without overwriting the winning row. A later
suffix failure can retain an acknowledged migrated prefix; a native commit whose
acknowledgement is lost can retain the current destination and conservative pending
storage reservation. The fixed migration/startup refusal makes no whole-success
claim, retry, rollback or refund. A later fresh explicitly enabled attempt validates
actual V2 without a second migration checkpoint and still needs original native
paid authority. Missing authority requires refusal and operator escalation within
remaining original operations work. These proofs are point-in-time preparation,
not an atomic multi-record transaction, census or backup/restore certificate.
