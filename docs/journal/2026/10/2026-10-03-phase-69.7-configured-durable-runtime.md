## Causal boundary and settled decisions

Original per-candidate recovery installs genuine paid native bindings and due work.
If composition were to release the first recovered candidate before checking a later
refused candidate, a Task could execute during a failed batch. The frozen solution
enters the original fresh-engine barrier before the factory/probe/source, fetches one
candidate vector, runs original terminal/runtime coordinators with that same vector,
and requires Registered terminal XOR runtime for every original identity/ordinal.
Only final atomic publication clears initialization and releases original workers.
A failed suffix retains paid prefix authority; no reconstruction, refund or rollback
is claimed. DL2's actual source barrier is before authentication and does not impose
an unlocked-authentication claim on the original native State monitor.

Runtime configuration preflight precedes component bootstrap/extras, final descriptor
verification, SPI resolution and StartupImport. Activating a provider at preflight
would expose incomplete assembly and the wrong cleanup boundary. Value-only typed
admission now remains at preflight; exact registered provider activation occurs at the
end of actual CLI initialization within original startup cleanup. The same original
engine/State/time/timer and actual SystemNode-bound managed pool own all effects.

Revision3 explicitly preserves original State-monitor authentication/registration,
projection, cancellation and due critical sections as normative read-only dependencies.
New composition adds no enclosing engine/Subsystem/owner I/O monitor. Brief original
engine-to-Subsystem final publication follows completed recovery, while shutdown
releases Subsystem monitor before original quiesce, owner stop and binding drain.

DL3 uses the original realtime ScheduledJobTimer's native shutdownNow inside the
already-begun provider factory, then returns valid actual managed native inputs.
Maintenance registration on that closed scheduler throws its native rejection;
fixed startup refusal and actual owned CLI failure cleanup are executable assertions.
No replacement timer, reflection, injection API or unowned source change is involved.
