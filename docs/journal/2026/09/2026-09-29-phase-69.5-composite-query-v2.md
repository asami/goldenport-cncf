# Phase 69.5 CompositeQuery v2

Date: 2026-09-29

JM69-07 / JM69-07A records the parent-frozen CompositeQuery v2 contract.
The implementation adds versioned request, protocol, coordinator, context, and
Job-task adapters plus executable specifications. It preserves v1 API and page
consumer behavior and does not modify the Job engine, Subsystem, context,
UnitOfWork, ComponentLogic, or WebPageContext owners.

The runtime policy is caller-owned bounded CNCF Job scheduling; direct Query
execution is target-owned and authorization remains at the target query-only
boundary. V2 jobs are ephemeral by default. Explicit persistent diagnostics
retain only sanitized lifecycle facts and no query input, response, secret, or
calltree payload.

Focused validation passed: 31 CompositeQuery v2 specifications and 41 affected
consumer specifications, with zero failures. Both serialized SBT invocations
completed with their locks released. No CNCF compiler warning was observed;
the pre-existing Java 25/Scala 3.3.8 Unsafe runtime warnings remain outside this
Step's scope.

The independent protected Step review identified internal identifier naming
and missing public-facade coverage in E28. One bounded repair flattened the
internal/local identifiers and made E28 exercise executeV2Blocking with actual
Given/When/Then setup while retaining V1 compatibility assertions. Independent
focused re-review P695-JM69-07-step-rereview-01 returned PASS and closed both
findings. The Step is accepted for local commit; the comprehensive Phase review
and final Phase release commit remain pending.

The command-runner recovery policy was repaired in development-workstation:
an unstarted runner may resume once from the original immutable intake after
structured-request storage loss or a transport-only locator failure. It must
retain the renderer's complete request before executing it in a separate call.
The real resumed consumer validation passed all 41 tests. This recovery creates
no new command authority, SBT attempt, or Phase repair cycle.

The repository-full acceptance remains deferred to the declared Phase 69.7
aggregate owner. Phase 69.6 receives only the frozen composition handoff; it
does not begin successor implementation here.
