The decision resolves the publication/disclosure profile left open by the
Phase 59 proposal. It does not change the closed Phase 58 resolver, resource
identity, authorization, or runtime-activation contracts.

## Frozen Profile

### Manuals and render projections

- SmartDox `.dox` is the canonical authored manual form.
- `.md` and `.markdown` are admitted Markdown inputs and are projected through
  the selected SmartDox Markdown profile.
- Existing `.adoc`, `.asciidoc`, and `.html` manuals remain supported as
  compatibility inputs. They are static packaged manual resources, not equal
  canonical SmartDox authoring forms and not implicit SmartDox conversion
  inputs.
- HTML is the required generated manual projection. PDF is optional; its
  absence must not make an otherwise valid release incomplete.

### Scaladoc

- A Component Scala API packages its public Scaladoc surface and its generated
  search/symbol evidence. Internal/private members are not promoted by the
  DOC-03 packaging profile.
- Release Scaladoc has no source links by default. A later explicit,
  authorized public-source disclosure record may permit them; a source path,
  source link, or source byte never establishes disclosure authority by
  itself.

### Release source

- Release source remains a required logical release concern: it is not silently
  omitted.
- Publicly disclosable release source is packaged through the SourceCode
  delivery profile with its source inventory, reproducibility provenance, and
  declared license/disclosure evidence.
- Restricted source is represented by its SourceCode identity and explicit
  access-policy evidence, but its content is not copied to a public archive,
  log, diagnostic, index, RAG context, or MCP response.
- The source-policy implementation must make the public/restricted declaration
  explicit and reject a release that has neither admitted public source nor
  an explicit restricted SourceCode representation. It must preserve the
  Phase 58 separation of inventory, authorization, integrity, availability,
  and disclosure.

## Consequences

The next DOC-03 implementation plans may add the corresponding deterministic
authoring, packaging, and strict-readiness checks. They must not infer
authorization from SourceCode membership, introduce a second resolver, or
turn optional PDF rendering into a release dependency.
